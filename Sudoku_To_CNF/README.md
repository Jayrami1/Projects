## Translation To CNF

#### Files Included

- [sudoku2cnf.ml](sudoku2cnf.ml) : OCaml file that converts a given sudoku format to cnf Dimacs format for z3 by making appropriate clauses.
- [sol2grid.ml](sol2grid.ml) : OCaml file to convert output of z3 to human-readable sudoku format again.
- [multisol.ml](multisol.ml) : OCaml file that checks multiple solution (>1) are possible for given sudoku.
- [check_sudoku.ml](check_sudoku.ml) : Already provided by TAs in piazza.
- [input.txt](input.txt) - Sudoku input to be given in either 1-9 format (n<=3) or 0-F format (n = 4) and unknown representated by  " . " . 
- [Makefile](Makefile) - Makefile compiles the files using compile then runs the compiled files using run and return Multiple Solutions if exists else unique solution on terminal. Clean command is used to delete any created files like compiled files and outputs.
>make compile
>make run
>make clean
>
#### Generated Files
- **problem.cnf** - [sudoku2cnf.ml](sudoku2cnf.ml) generates this file which includes all clauses included variable count, number of clauses and clauses itself in DIMACS form for Z3 solver.
- **sat_output.txt** - z3 -dimacs problem.cnf generates this file which includes solution for all variables whether they are present or not or whether the cnf clauses can be solved successfully. Input for [sol2grid.ml](sol2grid.ml).
- **output.txt** - Output by [sol2grid.ml](sol2grid.ml) using sat_output.txt and converts it into human-readable sudoku.
- **multiple_check.cnf** - Output by [multisol.ml](multisol.ml) which adds another clause which is neg list to current solution and input to z3 -dimacs multi_check.cnf.
- **sat_output1.txt** - Output by z3 -dimacs multi_check.cnf to make sure whether more than one solution exists.
- *.cmi *.cmo files are intermediate object files generated by compiling the code.

#### Approach and Methodology
##### Clause generator logic : 
- The preprocessor code maainly reduces the sudoku rules and expressed in the form of clause in **Conjuctive Normal Form**.
- The cases are mainly divided in the cases of n=3 and n=4.
- Each cell is given a unique id based on their row, col and value present there represented by
$$\text{}ID = (r - 1) \times N^2 + (c - 1) \times N + v$$
- Constraints are mainly divided into four cases.
- **Cell** - Each cell in (r,c) is represented uniquely using the get_id function and will have exactly one value only.
&emsp; - **Atleast one condition** - Ensures that no cell is empty and has atleast one val.
$$(x_{r,c,1} \lor x_{r,c,2} \lor \dots \lor x_{r,c,16})$$
&emsp; - **Atmost one condition** - Ensures that Ensures that no cell has more than one value in it.
$$\forall v_1, v_2 \in \{1 \dots 16\}, v_1 \neq v_2 : (\neg x_{r,c,v_1} \lor \neg x_{r,c,v_2})$$
- **Row/Column** -  Each row and column should have unique element from 1-9 or 0-F depending on the value of n. This is ensured by exactly one condition in each row and column.
$$(x_{r,1,v} \lor x_{r,2,v} \lor \dots \lor x_{r,16,v})$$
$$\forall c_1, c_2 \in \{1 \dots 16\}, c_1 \neq c_2 : (\neg x_{r,c_1,v} \lor \neg x_{r,c_2,v})$$
- **Block** - Each $ n \times n  $ block should have unique elements, ensured by exactly one condition in each block.
$$\bigvee_{i=0}^{3} \bigvee_{j=0}^{3} x_{R+i, C+j, v}$$
$B = \{(r, c) \mid R \le r < R+n, C \le c < C+n\}$.
$$\forall (r_1, c_1), (r_2, c_2) \in B \text{ where } (r_1, c_1) \neq (r_2, c_2) : (\neg x_{r_1, c_1, v} \lor \neg x_{r_2, c_2, v})$$
- **Input Specific** - Depending on given input in input.txt whether an element is present or not is given to the clauses for simplification.
**Note :** Although the conditions of atmost one in case of rows, columns and blocks are redundant, they make the sat solver much faster by pruning several branches of boolean decision diagram by enforcing an extra condition.
The input given to sudoku through input.txt is pipelined to problem.cnf for z3 solver . 
> ./sudoku2cnf input.txt > problem.cnf
>

##### SAT output to grid logic:
- The output of this is pipelined to sat_output.txt.
> z3 -dimacs problem.cnf > sat_output.txt
>
- This sat_output.txt is used bu sol2grid to convert the sat_format back to human-readable sudoku format  output.txt. Positive values in the sat format are ids of variable to be included in the solved part. These are separated using filter function from class.
> ./sol2grid sat_output.txt > output.txt
>

##### Multiple solution check logic :
- After solving the sudoku, the sat output is given to [multisol.ml](multisol.ml).
- This file converts pre-exisiting problem.cnf file and add an additional clause which is **NAND** of current solution to create a blocking clause and make sure that an exact same solution is not generated. 
- This new cnf file multiple_check.cnf again given to z3 -dimacs solver to check whether it is satisfiable or not. If not then it has unique solution else it has multiple solutions.
>./multisol sat_output.txt problem.cnf
>z3 -dimacs multiple_check.cnf > sat_output1.txt
>
#### Correctness :
##### Soundness : If SAT, then Sudoku
The solution is sound if every output of z3 is a valid sudoku.
&emsp; - **Atmost one condition**: - This prevents the solver to give multiple values in same cell or row/col, thus satisfying sudoku conditions.
&emsp; - **Conflict Prevention**: Because every rule of Sudoku is represented as a clause, any assignment that satisfies the CNF must, by definition, not violate any sudoku rule. 
&emsp; - **Initial Conditions**: Since initial grid values are present in the clauses itself the solver cannot overwrite them justifying their presence in the end sudoku.
##### Completeness : If sudoku, then SAT 
The solution is complete if for all instances of a valid sudoku, i can find an assignment of variables in SAT for a valid solution.
&emsp; - **Variable count** - Since $\text{} N^3 $ variables are created (where N is grid size), therefore
all posible conditions of row , column and value can be attained.
&emsp; - **Atleast one** - Since atleast one condition is applied no cell can be empty thus forcing all cells to be filled.
&emsp; - **No invalid solutions**- Since the conditions applied are constraints in sudoku, no case is possible for an invalid sudoku as answer or no answer that satisfies is left behind.
##### Uniqueness : PigeonHole Principle (PHP)
PigeonHole principle states that if number of pigeons are more than number of holes then at least one hole will have more than one pigeon in them. 
In sudoku 
- **Cell Uniqueness**: There are $N$ possible values (pigeons) and 1 cell (hole). The At Most One constraint ensures that if we have $N$ pigeons, at most 1 can fit.

- **Row/Column Uniqueness**: There are $N$ cells in a row (holes) and $N$ unique values required by the At Least One row constraint (pigeons).
&emsp; - If every value must appear at least once in the row, and there are exactly $N$ holes, the Pigeonhole Principle dictates that each value must appear exactly once.
&emsp;- If any value appeared twice, another value would have no "hole" left, violating the "At Least One" requirement.
